# Transfert X11

Le transfert X11 permet à un programme graphique qui tourne sur un serveur d'afficher sa fenêtre sur votre ordinateur. Avec OpenSSH, on utilise `ssh -X`, qui demande `xauth` et fonctionne mal sous Windows. Tunneler a sa propre implémentation et n'a pas besoin du binaire `xauth`.

## Prérequis

- **Un serveur X local.** Sous Windows, VcXsrv ou un autre serveur X pour Windows. Sous Linux, Xorg ou Xwayland, que votre session de bureau fait déjà tourner.
- **X11 autorisé sur le serveur.** `X11Forwarding yes` dans le `sshd_config` du serveur, et un client X comme `xeyes` ou votre éditeur sur le serveur.
- **Au moins un tunnel passant par l'hôte.** Le bouton X11 se trouve dans l'en-tête du groupe d'un hôte dans la liste des tunnels, et un hôte sans tunnel n'a pas de groupe.

Tunneler doit connaître votre display local. Il prend le premier de ces choix :

1. Le `x11_display` de cet hôte, sous `[hosts.<alias>]` dans `tunnels.toml`.
2. « Display X11 local » dans les paramètres.
3. La variable d'environnement `DISPLAY`. Sous Windows, quand elle n'est pas définie, `127.0.0.1:0.0`.

Si un fichier `Xauthority` local contient un cookie pour ce display, Tunneler l'utilise. Sans cookie, par exemple avec VcXsrv lancé avec « Disable access control », il se connecte sans.

## Démarrer l'ancre

Pour chaque hôte, Tunneler garde un canal X11 ouvert, appelé l'ancre. Il demande un display au serveur et le tient.

1. Dans l'en-tête du groupe de l'hôte, cliquez sur le bouton « X11 pour nova ».
2. Dans le panneau « X11 : nova », cliquez sur « Démarrer X11 » et confirmez « Activer X11 pour nova ? » après avoir lu l'avertissement.
3. Quand l'état indique « X11 actif », la section « Display distant » montre le display que le serveur vous a donné, par exemple `localhost:10.0`.
4. Cliquez sur « Copier export DISPLAY=localhost:10.0 ».

Tout programme lancé sur le serveur avec ce `DISPLAY` ouvre maintenant sa fenêtre sur votre écran. Dans un terminal sur le serveur :

```sh
export DISPLAY=localhost:10.0
xeyes &
```

L'ancre reste jusqu'à ce que vous cliquiez sur « Arrêter X11 » ou que vous quittiez Tunneler. Elle n'est pas redémarrée au lancement suivant.

::: warning
Le transfert X11 donne au serveur un accès complet à votre affichage local : il peut capturer le clavier et l'écran. N'activez X11 que pour des hôtes de confiance.
:::

## Lanceurs

Un lanceur est une commande enregistrée que Tunneler exécute sur le serveur avec X11 transféré vers votre display. Les lanceurs se déclarent dans `tunnels.toml` ; le panneau liste ceux de l'hôte dans sa section « Lanceurs », chacun avec un bouton « Lancer ».

```toml
[[x11_launchers]]
host = "nova"
name = "VS Code"
command = "code --wait"

[[x11_launchers]]
host = "nova"
name = "Terminal"
command = "xterm"
```

Un nom est unique par hôte.

## Un autre display pour un hôte

Si un hôte doit afficher sur un autre serveur X, réglez-le pour cet alias :

```toml
[hosts.nova]
x11_display = "198.51.100.135:0.0"
```

Le format est `hôte:display.écran`, comme dans `DISPLAY`.
