# X11 forwarding

X11 forwarding lets a graphical program running on a server draw its window on your computer. With OpenSSH you use `ssh -X`, which needs `xauth` and does not work well on Windows. Tunneler has its own implementation and does not need the `xauth` binary.

## Requirements

- **A local X server.** On Windows, VcXsrv or another X server for Windows. On Linux, Xorg or Xwayland, which a desktop session already runs.
- **X11 allowed on the server.** `X11Forwarding yes` in the server's `sshd_config`, and an X client such as `xeyes` or your editor on the server.
- **At least one tunnel through the host.** The X11 button sits in the header of a host's group in the tunnel list, and a host with no tunnel has no group.

Tunneler needs to know your local display. It uses the first of these:

1. The `x11_display` of that host, under `[hosts.<alias>]` in `tunnels.toml`.
2. "Local X11 display" in the settings.
3. The `DISPLAY` environment variable. On Windows, when it is not set, `127.0.0.1:0.0`.

The "X11" drawer shows the local display actually used: the host's `x11_display`, else the general setting, else the `DISPLAY` variable. Change the general setting in Settings > Connection.

If a local `Xauthority` file holds a cookie for that display, Tunneler uses it. Without one, for example with VcXsrv started with "Disable access control", it connects without a cookie.

## Start the anchor

For each host, Tunneler keeps one X11 channel open, called the anchor. It asks the server for a display and holds it.

1. In the host's group header, click the "X11 for nova" button.
2. In the "X11: nova" drawer, click "Start X11" and confirm "Enable X11 for nova?" after reading the warning.
3. Once the state reads "X11 active", the "Remote display" section shows the display the server gave you, such as `localhost:10.0`.
4. Click "Copy export DISPLAY=localhost:10.0".

Any program that runs on the server with that `DISPLAY` now opens its window on your screen. In a terminal on the server:

```sh
export DISPLAY=localhost:10.0
xeyes &
```

The anchor stays until you click "Stop X11" or quit Tunneler. It is not started again at the next launch.

::: warning
X11 forwarding gives the server full access to your local display: it can capture the keyboard and the screen. Only enable it for hosts you trust.
:::

## Launchers

A launcher is a saved command that Tunneler runs on the server with X11 forwarded to your display. Launchers are declared in `tunnels.toml`; the drawer lists those of the host in its "Launchers" section, each with a "Launch" button.

```toml
[[x11_launchers]]
host = "nova"
name = "VS Code"
command = "code --wait"

[[x11_launchers]]
host = "nova"
name = "Terminal"
command = "xterm"
```

A name is unique per host.

## A different display for one host

If one host should draw on another X server, set it for that alias:

```toml
[hosts.nova]
x11_display = "198.51.100.135:0.0"
```

The format is `host:display.screen`, as in `DISPLAY`.
